> v1.0 → v1.1 변경 (2026-11-21): 파일럿 지역 확정(베를린·프랑크푸르트), 상태와 적용 여부 분리, 도착일·지역 코드 추가, 추천/대화 저장 요구사항 추가, 모든 수용 기준을 테스트 가능한 형식(AC-ID, Given/When/Then)으로 재작성. 근거: `docs/PHASE0_ANALYSIS.md` §1.3, `docs/DECISIONS.md`.

## 1. 제품 개요
- 제품명: Cross-border Life OS
- 한 줄 설명: AI-powered Relocation Assistant
- 초기 타깃: 한국에서 독일 **베를린 또는 프랑크푸르트 암 마인**으로 이주하는 개인/부부/가족
- 핵심 문제: 이주 업무가 여러 기관과 웹사이트(대부분 독일어)에 흩어져 있고, 선행 조건과 일정이 복잡해 누락·지연이 발생한다.
- 언어: UI와 답변은 한국어. 공식 출처 제목은 원문 유지.

## 3. 주요 사용자 여정
1. 사용자가 상황을 자연어로 쓰거나 폼에 최소 정보를 입력한다.
2. 시스템은 프로필 초안을 만들고, 필드별 신뢰도와 누락 정보를 보여준다.
3. 사용자가 초안을 확인·수정한 뒤 저장한다.
4. 시스템은 **검증된 업무 템플릿과 결정론적 적용 규칙**으로 업무 후보를 제안한다(LLM이 업무를 새로 만들지 않음).
5. 사용자는 업무를 체크리스트에 추가하거나 제외한다.
6. 업무별 설명, 선행 업무, 준비 자료, 공식 출처(기관·제목·URL·확인일)를 확인한다.
7. 사용자는 상태와 목표일을 업데이트한다.
8. 시스템은 실행 가능한 업무 중에서 다음 행동을 추천하고 이유를 설명한다.
9. 사용자는 언제든 공식 출처 기반 Q&A를 사용한다.

## 4. 용어
| 용어 | 정의 |
|---|---|
| 상태 (`status`) | `not_started` / `in_progress` / `blocked` / `completed` — 사용자 진행 상황 |
| 적용 여부 (`applicability`) | `applies` / `needs_review` — 이 업무가 사용자에게 해당하는지에 대한 시스템 판단. 상태와 별개 |
| 제외 (`is_excluded`) | 사용자가 체크리스트에서 뺀 업무. 진행률·추천에서 제외 |
| 실행 가능 업무 | 미완료·미제외이며 모든 hard 선행 업무가 `completed`인 업무 |
| 확정 기한 | 템플릿의 `deadline_rule`이 존재하고, 그 규칙을 뒷받침하는 공식 출처(`supports=deadline`)가 있으며, 기준일(도착일 등)이 입력된 경우에만 계산되는 날짜 |
| 사용자 목표일 | 사용자가 직접 정한 날짜. 확정 기한과 시각적으로 구분 |

## 5. 기능 요구사항

수용 기준(AC)은 각각 자동 테스트 또는 평가 케이스로 검증합니다. `[unit]` 단위 테스트, `[int]` DB 통합 테스트, `[e2e]` 브라우저 테스트, `[eval]` AI 평가 케이스.

### FR-01 프로필
- 필드: `origin_country`(KR 고정), `destination_country`(DE 고정), `move_purpose`, `target_move_date`, `arrival_date`, `household_type`, `housing_status`, `state_code`, `city`
- `move_purpose`: `employment` / `job_seeking` / `study` / `family_reunion` / `self_employed` / `other`
- `household_type`: `single` / `couple` / `family_with_children`
- `housing_status`: `none` / `temporary` / `permanent`
- 필수: `move_purpose`, `city` (나머지는 선택)
- 수집 금지: 여권번호, 계좌번호, 세금 식별번호, 건강정보, 정확한 주소

| AC | 기준 | 검증 |
|---|---|---|
| AC-01-1 | Given 필수 필드가 비어 있을 때 When 저장하면 Then 저장되지 않고 필드별 오류 메시지가 표시된다 | [unit][e2e] |
| AC-01-2 | Given 자연어 입력 When AI가 구조화하면 Then 결과는 스키마를 통과하고, 저장 전 확인 화면에 필드별 값·신뢰도가 표시된다 | [unit][eval] |
| AC-01-3 | Given 입력에 언급되지 않은 정보 When 구조화하면 Then 해당 필드는 추측값 대신 `null` + `missing_fields`에 포함된다 | [eval] |
| AC-01-4 | Given 입력에 여권번호·계좌번호 등 패턴 When 구조화 요청하면 Then LLM 호출 전 마스킹되고 사용자에게 경고가 표시된다 | [unit] |
| AC-01-5 | Given 지원 도시가 아닌 곳 When 저장하면 Then 저장은 되며 "연방 공통 업무만 제공" 안내가 표시된다 | [unit][e2e] |
| AC-01-6 | Given 사용자 A When 사용자 B의 프로필을 조회·수정하면 Then 거부된다 | [int] |

### FR-02 업무 템플릿 및 체크리스트
- 템플릿 필드: 제목, 설명, 카테고리, 적용 규칙, 선행 업무, 필요 자료, 예상 소요(검증된 경우만), 지역 범위, 공식 출처(뒷받침하는 사실 유형 포함), 검증 상태, 검증일. 상세 형식은 `docs/DATA_SPEC.md`.
- 카테고리: `housing_registration`, `residence_admin`, `finance_tax`, `insurance`, `telecom`, `driving_vehicle`

| AC | 기준 | 검증 |
|---|---|---|
| AC-02-1 | Given 프로필 When 체크리스트를 생성하면 Then 적용 규칙을 만족하는 `verified` 템플릿만 `applies`로, 규칙 판단에 필요한 프로필 값이 없으면 `needs_review`로 제안된다 | [unit] |
| AC-02-2 | Given 지역 범위가 다른 도시인 템플릿 When 생성하면 Then 제안되지 않는다 | [unit] |
| AC-02-3 | Given 업무 When 상태를 변경하면 Then 저장되고 진행률이 즉시 재계산된다 (진행률 = completed ÷ 제외되지 않은 업무) | [unit][int][e2e] |
| AC-02-4 | Given 업무 When 제외하면 Then 진행률과 추천 후보에서 빠지고, 다시 포함할 수 있다 | [unit][int] |
| AC-02-5 | Given 출처가 없는 템플릿 When 시드하면 Then `verified`로 저장할 수 없다 | [int] |
| AC-02-6 | Given 업무 상세 When 열면 Then 출처마다 기관·제목·URL·확인일이 표시되고, 확인일이 90일 넘으면 "재확인 필요" 배지가 붙는다 | [unit][e2e] |
| AC-02-7 | Given 사용자 정의 업무 When 추가하면 Then 템플릿 없이 생성되며 "사용자 추가" 표시가 붙고 출처는 비어 있다 | [int] |

### FR-03 타임라인
- 구간: 출국 전 / 도착 후 / 정착 이후. 날짜 미정 업무는 별도 "날짜 미정" 레인.

| AC | 기준 | 검증 |
|---|---|---|
| AC-03-1 | Given 확정 기한도 사용자 목표일도 없는 업무 When 타임라인에 표시하면 Then 날짜 없이 "날짜 미정" 레인에 놓인다 | [unit][e2e] |
| AC-03-2 | Given 기한 규칙이 있으나 기준일(예: 도착일)이 없을 때 When 표시하면 Then "도착일 입력 시 계산" 안내가 붙는다 | [unit] |
| AC-03-3 | Given 확정 기한과 사용자 목표일 When 표시하면 Then 두 종류가 아이콘·텍스트로 구분된다 | [e2e] |
| AC-03-4 | Given hard 선행 업무가 미완료 When 표시하면 Then 해당 업무에 "선행 업무 대기" 표시와 선행 업무 링크가 있다 | [unit][e2e] |
| AC-03-5 | Given 템플릿 선행 관계 When 시드하면 Then 순환이 있으면 시드가 실패한다 | [unit] |

### FR-04 RAG 행정 가이드
| AC | 기준 | 검증 |
|---|---|---|
| AC-04-1 | Given 답변 When 반환하면 Then 모든 사실 주장(claim)에 이번 검색 결과의 chunk가 1개 이상 연결되어 있고, 연결이 검증되지 않은 claim은 표시되지 않는다 | [unit][eval] |
| AC-04-2 | Given 관련 문서가 없거나 관련도가 기준 미만 When 질문하면 Then `insufficient_evidence` 상태로 "공식 확인 필요"와 관련 기관 안내를 반환한다 | [eval] |
| AC-04-3 | Given 비자·세무·법률 자격 판정 질문 When 질문하면 Then `out_of_scope`로 판정을 거부하고 일반 정보·관할 기관을 안내한다 | [eval] |
| AC-04-4 | Given 검색 문서에 지시문이 삽입됨 When 답변하면 Then 지시를 따르지 않는다 | [eval] |
| AC-04-5 | Given 출처 카드 When 렌더링하면 Then 기관·제목·URL·확인일은 DB 값이며 LLM 출력이 아니다 | [unit] |
| AC-04-6 | Given 모든 답변 When 표시하면 Then "일반 정보이며 법률 자문이 아님" 고지가 표시된다 | [e2e] |

### FR-05 Next Best Action
| AC | 기준 | 검증 |
|---|---|---|
| AC-05-1 | Given 업무 목록 When 추천하면 Then 추천 업무는 항상 실행 가능 업무 집합에 속한다 (집합 밖 ID는 서버가 폐기) | [unit][eval] |
| AC-05-2 | Given 추천 When 표시하면 Then 이유, 필요한 준비 자료, 근거 출처가 함께 표시된다 | [unit][e2e] |
| AC-05-3 | Given 확정 기한이 아닌 날짜 When 추천 이유를 만들면 Then "마감"·"긴급" 표현을 쓰지 않는다 | [eval] |
| AC-05-4 | Given 추천 When 수락/무시하면 Then 상태가 저장되고 무시한 추천은 다음 추천에서 제외된다 | [int] |
| AC-05-5 | Given 실행 가능 업무가 없음 When 추천하면 Then 막힌 이유(대기 중인 선행 업무)를 안내한다 | [unit] |

## 6. 비기능 요구사항
- 반응형: 모바일(사이드바 → drawer) 및 데스크톱
- 보안: RLS로 사용자별 데이터 분리, 비밀키는 서버 환경변수에만
- 개인정보: 자연어 원문 입력은 저장하지 않음. 로그에는 입력 해시만
- 접근성: WCAG 2.1 AA 대비, 키보드 포커스, 상태를 색상 + 텍스트/아이콘으로 표시
- 관측성: AI 요청 실패·검색 실패·스키마 검증 실패를 `ai_runs`에 기록
- 모든 주요 화면에 로딩/빈/오류 상태

## 7. MVP 제외 범위
- 기관에 대한 자동 제출/예약
- 법률·세무·비자 자격 판정
- 결제/구독
- 베를린·프랑크푸르트 외 지역별 절차
- 문서 업로드
- 자동 웹 크롤러 (출처는 수동 큐레이션)
- 알림/이메일

## 8. 초기 데이터 전략
- 업무 템플릿 30개(6개 카테고리 × 약 5개): 연방 공통 + 베를린 + 프랑크푸르트 지역 업무
- 출처는 공식 기관(`official`)을 우선하고, 보조 출처(`secondary`)는 공식 출처가 없을 때만 사용하며 화면에 구분 표시
- 공식 출처로 확인되지 않은 필드는 비워두고 템플릿을 `needs_review`로 둔다
- 모든 템플릿은 PR 리뷰로 추가·수정한다 (git 이력이 곧 검증 이력)
