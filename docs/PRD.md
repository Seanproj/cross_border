# Product Requirements Document (PRD)

## 1. 제품 개요
- 제품명: Cross-border Life OS
- 한 줄 설명: AI-powered Relocation Assistant
- 초기 타깃: 한국에서 독일로 이주하는 개인/부부
- 핵심 문제: 이주 업무가 여러 기관과 웹사이트에 흩어져 있고, 선행 조건과 일정이 복잡해 누락·지연이 발생한다.

## 2. 사용자 페르소나
한국에서 독일로 이주를 준비하거나 막 정착한 사용자. 행정 경험이 부족하고, 어떤 일을 언제 어떤 순서로 해야 하는지 알고 싶다.

## 3. 주요 사용자 여정
1. 사용자가 출발 국가, 도착 국가, 이주 목적, 대략적인 이주일, 주거 상태 등 최소 정보를 입력한다.
2. 시스템은 프로필을 구조화하고 누락된 필수 정보를 질문한다.
3. 규칙 기반 필터와 AI 분류를 조합해 관련 업무 후보를 제시한다.
4. 사용자는 업무를 체크리스트에 추가하거나 제외한다.
5. 업무별 설명, 선행 조건, 준비 자료, 공식 출처를 확인한다.
6. 사용자는 상태와 목표일을 업데이트한다.
7. AI는 현재 상태를 바탕으로 다음 행동을 추천한다.

## 4. 기능 요구사항

### FR-01 프로필
- 프로필 생성/수정
- 필드: origin_country, destination_country, move_purpose, target_move_date, household_type, housing_status, region_or_city
- 민감한 식별정보는 수집하지 않는다.
- 사용자는 AI가 추출한 내용을 확인하고 수정할 수 있어야 한다.

수용 기준:
- 필수 입력 누락을 안내한다.
- 구조화 결과를 저장하기 전 사용자가 확인할 수 있다.
- 잘못된 입력에 대한 검증 메시지를 제공한다.

### FR-02 업무 템플릿 및 체크리스트
각 업무는 제목, 설명, 카테고리, 적용 조건, 선행 업무, 필요 자료, 예상 소요 시간(검증된 경우), 공식 출처, 검증일을 포함한다.
- 사용자는 업무 추가/제외/상태 변경을 할 수 있다.
- 적용 조건이 불명확한 업무는 "확인 필요" 상태로 표시한다.

수용 기준:
- 사용자가 업무 상태를 변경할 수 있다.
- 완료한 업무는 타임라인과 진행률에 반영된다.
- 출처가 없는 법적 의무/기한은 자동 생성하지 않는다.

### FR-03 타임라인
- 목표 이주일 또는 사용자가 설정한 날짜를 기준으로 업무를 표시한다.
- 선행 조건이 있는 업무는 의존 관계를 표시한다.
- 확정되지 않은 날짜는 "예정" 또는 "사용자 설정 필요"로 표현한다.

수용 기준:
- 날짜가 없는 업무가 잘못된 확정 날짜로 표시되지 않는다.
- 선행 업무가 완료되지 않은 업무는 의존 상태를 표시한다.

### FR-04 RAG 행정 가이드
- 승인된 출처 문서를 검색한다.
- 답변에 출처 제목, 기관, URL, 확인일을 제공한다.
- 검색 결과가 부족하면 추측하지 않고 한계를 설명한다.
- 답변을 법률·세무·비자 판정으로 표현하지 않는다.

수용 기준:
- 각 사실 주장에 근거 문서가 연결된다.
- 근거가 없는 질문에는 불확실성을 명시한다.
- 검색 문서의 악성 지시문을 무시한다.

### FR-05 Next Best Action
- 미완료 업무, 의존성, 사용자 목표일, 확인된 기한을 고려한다.
- 추천 업무, 추천 이유, 필요한 선행 조건, 근거 출처를 반환한다.
- 사용자는 추천을 수락/무시할 수 있다.

수용 기준:
- 추천 이유를 사용자에게 설명한다.
- 미확인 기한을 긴급 마감으로 표시하지 않는다.
- 선행 조건이 충족되지 않은 작업을 실행 가능한 것처럼 추천하지 않는다.

### FR-06 Evaluation
- 고정된 질문/프로필 테스트 세트를 실행할 수 있다.
- 정확성, 근거성, 완전성, 불확실성 처리, 안전성을 평가한다.
- 모델/프롬프트 버전별 결과를 기록한다.

## 5. 비기능 요구사항
- 반응형: 모바일 및 데스크톱
- 보안: 사용자별 데이터 분리, 서버 측 비밀키 관리
- 성능: 주요 대시보드의 일반적인 로딩을 체감상 빠르게 유지
- 접근성: 명확한 대비, 키보드 포커스, 의미 있는 레이블
- 관측성: AI 요청 실패와 검색 실패를 로그로 추적하되 민감정보는 기록하지 않음

## 6. MVP 제외 범위
- 기관에 대한 자동 제출/예약
- 법률·세무 자문
- 결제/구독
- 모든 독일 주/도시별 절차 완전 지원
- 한국/미국/독일의 모든 행정 절차 동시 지원

## 7. 초기 데이터 전략
초기에는 검증 가능한 업무 30~50개만 입력한다. 모든 절차는 관할 지역과 사용자 조건에 따라 달라질 수 있으므로, 업무 템플릿에 적용 범위와 확인일을 기록한다.
