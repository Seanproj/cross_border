# AI Evaluation Plan

## 1. 목적
AI 기능이 실제로 유용하고, 근거에 충실하며, 불확실한 상황에서 안전하게 동작하는지 반복 측정합니다.

## 2. 평가 대상
1. 프로필 구조화
2. RAG 답변
3. Next Best Action 추천

## 3. 테스트 세트
90일 목표: 최소 50개 케이스
- 15개 프로필 구조화
- 20개 공식 정보 Q&A
- 15개 다음 행동 추천

각 케이스에는 입력, 기대 조건, 금지 조건, 심각도를 기록합니다.

## 4. 평가 기준

| 지표 | 의미 | 평가 방법 |
|---|---|---|
| Schema Validity | 출력이 정의된 스키마를 만족하는가 | 자동 |
| Factual Accuracy | 핵심 사실이 근거와 일치하는가 | 사람 검토 + 기준 답안 |
| Groundedness | 주장마다 근거가 연결되는가 | 사람 검토 |
| Completeness | 중요한 절차/조건을 빠뜨리지 않는가 | 기준 체크리스트 |
| Abstention | 근거 부족 시 추측을 멈추는가 | 자동/사람 검토 |
| Actionability | 추천이 실행 가능하고 순서가 타당한가 | 기준 체크리스트 |
| Safety | 법적 판정·허위 기한·민감정보 요구를 피하는가 | 고위험 케이스 |

## 5. 초기 통과 기준
- 구조화 출력 유효성: 98% 이상
- 근거가 필요한 답변의 출처 연결률: 95% 이상
- 고위험 테스트에서 중대한 허위 법적 단정: 0건
- 추천 업무의 선행 조건 위반: 0건
- 전체 케이스 통과율: 목표 90%

수치는 초기 목표이며, 평가 데이터의 품질과 표본 수를 함께 공개합니다. 자동 LLM-as-judge 점수만으로 정확성을 주장하지 않습니다.

## 6. 필수 엣지 케이스
- 사용자 상황에 필수 정보가 빠진 경우
- 도시/주에 따라 절차가 달라지는 경우
- 오래된 공식 페이지와 최신 페이지가 충돌하는 경우
- 검색 결과가 없거나 관련성이 낮은 경우
- 사용자가 잘못된 전제를 포함한 질문을 하는 경우
- 문서 내부에 모델을 조종하려는 지시문이 있는 경우
- 날짜가 없거나 모호한 경우
- 비자/세무/법률 자격 판정을 요구하는 경우

## 7. 결과 공개
포트폴리오에는 다음을 공개합니다.
- 평가 데이터셋의 구성과 한계
- 모델명 및 프롬프트 버전
- 평가 시점
- 지표별 결과
- 대표 실패 사례와 수정 내용
- 자동 평가와 사람 평가의 구분

실제 사용자 개인정보, API 키, 비공개 문서 원문은 공개하지 않습니다.
